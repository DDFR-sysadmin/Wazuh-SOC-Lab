
# Wazuh SOC Laboratory Environment

Репозиторий содержит конфигурационные файлы, скрипты автоматизации и документацию для развертывания локальной лабораторной SIEM-среды на базе **Wazuh (v4.9.0)**. Проект ориентирован на симуляцию кибератак, мониторинг целостности файлов (FIM), анализ защищенности (SCA, Vulnerability Detector) и управление алертами в SOC.

## 🛠 Архитектура лабораторного стенда

1.  **Серверный хост (SIEM):** Ubuntu Server, развернутый в контейнеризованном окружении Docker.
    
    -   **Wazuh Manager** — ядро системы (сбор и анализ логов).
        
    -   **Wazuh Indexer** — поисковый движок на базе OpenSearch (индексация и хранение).
        
    -   **Wazuh Dashboard** — веб-интерфейс для визуализации и администрирования.
        
2.  **Анализируемый эндпоинт (Target):** Windows Server / Windows 10 с установленным Wazuh Agent и развернутым веб-сервером XAMPP (Apache + MySQL) для симуляции веб-уязвимостей.
    

## 🚀 Быстрое развертывание (Автоматизация)

Для минимизации рутинных действий написан Bash-скрипт автоматической установки, который самостоятельно настраивает зависимости, генерирует SSL-сертификаты и конфигурирует параметры безопасности.

### Особенности инсталлятора:

-   **Интективная настройка:** Скрипт запрашивает безопасный пароль для учетной записи `admin` и автоматически генерирует криптографический хэш (BCrypt) через утилиту `hash.sh` внутри временного контейнера, интегрируя его в `internal_users.yml`.
    
    
-   **Авто-оптимизация:** Скрипт сразу подтягивает кастомизированный `ossec.conf` для оптимизации дискового пространства.
    

Bash

```
# Запуск инсталлятора на чистой Ubuntu Server
chmod +x installer_wazuh.sh
sudo bash installer_wazuh.sh

```

## 📉 Оптимизация ресурсов в условиях Lab-окружения

Поскольку стандартные лимиты Wazuh рассчитаны на Production-нагрузки, в лабораторной среде применены жесткие ограничения для экономии RAM и Disk Space:

1.  **Ограничение Java Heap (RAM):** В `docker-compose.yml` для сервиса `wazuh.indexer` параметры виртуальной машины Java принудительно ограничены: `OPENSEARCH_JAVA_OPTS=-Xms512m -Xmx512m`. Это предотвращает утечку памяти и аварийную остановку контейнеров по механизму OOM (Out Of Memory).
    
2.  **Оптимизация баз CVE (Disk Space):** В кастомном `ossec.conf` менеджера оптимизирован модуль `vulnerability-detector`. Отключено скачивание ресурсоемких баз уязвимостей для неиспользуемых в лабе дистрибутивов Linux (RedHat, Arch, Debian), что экономит десятки гигабайт дискового пространства. В данной конкретной лабе нам нужны только базы nvd (National Vulnerability Database) и msu (Microsoft Security Updates). Однако я так же добавил и базу для ubuntu так как планирую проверять возможность атаки на сам сервер с SIEM.

## 🛡 Сценарии симуляции атак и верификации алертов

### 1. Тестирование FIM (File Integrity Monitoring)

-   **Действие:** Создание/изменение PHP-файлов в директории веб-сервера `C:/xampp/htdocs`.
    
-   **Ожидаемый результат:** Мгновенная генерация алерта в Wazuh Dashboard с фиксацией имени пользователя, изменившего файл, и точного времени изменения.
    

### 2. Эксплуатация SQL-инъекции с заливкой Веб-шелла

-   **Действие:** Проведение SQLi атаки на уязвимый скрипт с использованием конструкции `UNION SELECT ... INTO OUTFILE 'C:/xampp/htdocs/shell.php'`.
    
-   **Ожидаемый результат:** Комбинация двух типов алертов: срабатывание правил анализа веб-логов (парсинг аномальных SQL-запросов в Apache) + алерт от модуля FIM о появлении нового файла в корне веб-сервера.
